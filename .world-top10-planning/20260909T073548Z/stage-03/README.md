# STAGE-3-CORE — CORE

상태: **BLOCKED_PREREQUISITE**
진입 조건: 2단계 통과
종료 조건: 정상·빈·로딩·오류·복구 흐름이 인수 기준 통과

## 1. 쉬운 말 한 문장 목표

핵심 사용자 여정과 필수 기능를 3단계에서 재현 가능한 산출물로 만든다.

## 2. 사용자에게 보이는 단계 완료 모습

사용자는 3단계 완료 화면에서 상태·다음 행동·오류 복구를 이해한다.

## 3. 포함 범위

이 단계의 작업카드 TASK-3-001, TASK-3-002, TASK-3-003와 연결 시험 60개를 포함한다.

## 4. 명시적 제외 범위와 이유

제품 코드·설정·Git·공개 배포·B 드라이브는 분석 전용 범위에서 제외한다.

## 5. 진입 조건 체크리스트

진입: 2단계 통과. 체크: 원본 보존, 증거 ID, 명령, 담당자.

## 6. 이전 단계에서 받는 입력

이전 단계 2 인수 패킷과 차단 항목을 받는다.

## 7. 산출물 파일 목록

stage-03/tasks, tests, evidence와 루트 추적표를 만든다.

## 8. 요구사항·격차·결정 ID 목록

REQ-V33-003 계열, GAP/DECISION/IMP를 작업카드와 연결한다.

## 9. 작업 의존 관계와 실행 순서

선행 완료 후 카드 순서: TASK-3-001, TASK-3-002, TASK-3-003. 외부 차단은 READY로 승격하지 않는다.

## 10. 병렬 실행 가능 작업

문서·정적 분석·독립 브라우저 검사는 병렬 실행 가능하다.

## 11. 절대 순차 실행 작업

권한·비밀·공개·삭제·이전은 한 번에 한 환경에서 순차 실행한다.

## 12. 예상 변경 파일·기호·설정

분석 전용이므로 실제 변경 파일은 없음; 실행 시 카드의 전체 경로와 기호를 따른다.

## 13. 데이터·API·UI 계약 변화

HTTP·JSON·R2/D1·UI 상태·접근성 계약과 오류 코드를 고정한다.

## 14. 정상 흐름

정상: 입력→검증→처리→결과→증거 저장.

## 15. 빈·로딩·부분 성공 흐름

빈/로딩/부분 성공을 별도 문구와 재시도·초점 이동으로 표시한다.

## 16. 실패·권한 거부·오프라인·복구 흐름

실패·권한 거부·오프라인은 안전한 오류와 롤백 지점으로 복구한다.

## 17. 접근성·다국어·모바일·PC 조건

WCAG 2.2 AA, ko/en, 360/390px 및 PC 폭을 검사한다.

## 18. 보안·개인정보·권한 조건

OAuth state/CSRF·secret redaction·최소수집·삭제 요청을 강제한다.

## 19. 성능·용량·비용 예산

LCP 2.5s·CLS 0.1·TBT 200ms 목표와 무료 한도 예산을 기록한다.

## 20. 자동 시험 묶음

60개 고유 자동/계약 시험을 실행하고 실패 시 증거를 남긴다.

## 21. 수동·실기기·외부 서비스 시험 묶음

브라우저 자동 시험을 먼저 실행하고 실기기 상태는 별도 기록한다.

## 22. 중단 신호와 되돌리는 순서

비밀 노출·데이터 손상·오류율 상승 시 즉시 중단하고 safe_revert_sequence을 따른다.

## 23. 종료 조건과 필요한 증거

종료: 정상·빈·로딩·오류·복구 흐름이 인수 기준 통과. 현재 상태: BLOCKED_PREREQUISITE; 외부 차단 해소 전 완료 선언 금지.

## 24. 다음 단계 인계 체크리스트

다음 단계에 STAGE-3-CORE, 카드·시험·증거·미확인 DISCOVERY ID와 첫 명령을 전달한다.
